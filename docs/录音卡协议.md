行为基准为 Aipixdot 在线 Demo，核对日期 2026-11-11，脚本版本 `key-ack-1792409573820`，SHA-256 为 `f46f39f3646d76aa57e0eb75dde11897695441582b717b059c75ba1ad368e6b5`。网页更新时，先核对实际加载的脚本，再更新 SDK、回放样例和本文。命令表中的 `类型-命令` 使用十进制，字节串使用十六进制。[在线案例](https://aipixdot.com/airecord/) · [核对的脚本版本](https://aipixdot.com/airecord/app.js?v=key-ack-1792409573820)

## 会话

| 优先顺序 | 服务 | 写入 | 主通知 | 可选按键通知 |
| --- | --- | --- | --- | --- |
| 1 | AE20 | AE21 | AE22 | AE23 |
| 2 | AD40 | AD41 | AD42 | AD43 |

通过服务或 CB08 / QS668 名称前缀发现候选，同时存在两个服务时优先 AE20。只有首选服务缺失才采用 AD40。先启用主通知，再尝试按键通知；后者缺失或订阅失败时，只要数据通道正常即可就绪。同一次连接只有一个写队列，优先无响应写，支持仅有响应写的特征。每条命令只写一次整帧。两路通知各自缓存、校验和拆帧，再按类型分发。会话关闭时停止处理通知，清空待发送帧并取消巡检。中央管理器负责断开外设。

就绪后依次发送 `0-3、0-1、0-10、0-12、3-19、3-21、3-23、3-25、2-0`。每步写完到下一步约 260 毫秒，某项没有业务回复也继续。网页空闲后等用户操作、通知或再次巡检。桌面应用在录音计时、保存确认、可选按键通知不可用时会按业务需要读取状态；数据没有更新本身不会触发工作留声断开。桌面应用已有的绑定、断线重连、USB 切换和原件校验仍由业务层处理。

## 机身按键

以下字节为 payload。两路通知都可以交付按键。只有 TYPE=3、命令匹配且参数长度为零时回复；有参数的异常按键、偶数结果帧和单字节通用 ACK 不触发回包。收到合法请求立即把应答加入写队列，再通知录音业务。回复使用客户端当前发送序号。

| 机身操作 | 卡发出 | 客户端写回 |
| --- | --- | --- |
| 开始 | `03 01` | `03 02 01` |
| 保存 | `03 03` | `03 04 01` |
| 暂停 | `03 05` | `03 06 01` |
| 继续 | `03 07` | `03 08 01` |

例如客户端下一发送序号为 0，开始应答整帧为 `5A 00 C1 C1 03 00 03 02 01`。回复表明收到该按钮请求；保存完成仍应查设备空闲状态及文件。应用主动发起录音和对机身按键回包使用不同的命令。

## 帧与数据

`5A | SEQ | CRC16 LE | LEN16 LE | TYPE | CMD | PARAMS`。CRC-16/XMODEM 计算范围为 LEN 两字节和 payload；SEQ 为客户端发送计数器，255 后回到 0。每路解析器支持半帧、多帧及最大 8192 字节 payload。接收端与 Demo 一样接受零 CRC 兼容帧；其他错误 CRC 的整帧丢弃。发送始终计算 CRC。单字节 payload 是通用 ACK。

| 功能 | 命令与数据 |
| --- | --- |
| 信息与时钟 | `0-3 → 0-4` 电量，110 表示已充满。`0-1 → 0-2` 剩余/总量各 LE32，单位 KiB。`0-10 → 0-11` 固件，`0-12 → 0-13` 授权码。用户校时用 `0-0`，年 LE16，月日时分秒各一字节，无时区字段和时钟回读。 |
| 录音查询 | `3-19 → 3-20`，1 录音、2 空闲、3 暂停。`3-21 → 3-22` 秒数 LE16 和大小 LE32。`3-23 → 3-24` 文件名。`3-25 → 3-26` 增益，1/2/3 为低/中/高。设置增益为 `3-27`，`3-28` 结果 0 成功。 |
| 实时音频 | `1-0` 开始并返回文件名，`1-1` 推送 OPUS 数据，`1-3 01/00` 暂停/继续，`1-2` 结束。`1-4` 中 0/1/2 为继续/暂停/停止。普通录音的开始、保存、暂停、继续是 `3-1/3/5/7`；结果命令加一，结果字节 1 成功。 |
| 列表 | `2-0 → 2-1… → 2-18`。每个列表包先放 BE32 条数，每项是 BE32 时长、BE32 大小、20 字节文件名。旧固件给出条目后静默约 1.2 秒可展示已有项。没有任何回复不能证明卡为空。 |
| 完整或分段导入 | 完整文件 `2-2` 含 LE32 偏移和 24 字节补零文件名，整帧 36 字节。分段 `2-12` 含 LE32 Start、LE32 End 和变长 UTF-8 文件名。`2-3` 开始、`2-4` 数据、`2-5` 结束且结果 0 成功。`2-7` 终止，`2-11` 回应。网页导入无活动约 12 秒进入候选文件名重试或报错。SDK 原件归档另校验文件名、长度及音频格式。 |
| 删除 | `2-8` 携带所选列表项原始 28 字节，`2-13` 返回结果。`2-9` 清空全部，`2-10` 返回结果。两者均以 0 为成功。原始列表项包含完整字段，不能用文件名字符串替代。 |

## Swift 接入

中央管理器使用主队列。每次 `didConnect` 时创建并强持有一个 `RecorderGATTSession`，先设置回调再调用 `open()`。主通知订阅成功且可选按键订阅已有结果时触发 `onReady(hasKeys)`。业务层此时可以更新界面，会话随后交付订阅期间已收到的帧并自动开始首次巡检。

| 接入位置 | 调用方负责的事 |
| --- | --- |
| `onFrame(frame, channel)` | 处理设备状态、音频或文件。会话已将合法按键的应答加入写队列，业务层重复回包会让同一次按键得到两次确认。 |
| `onKeyAvailability` / `onWarning` | 可选按键订阅失效时保留主通道，并按业务需要查询录音状态。写入错误等警告通过 `onWarning` 交付。 |
| `onFailure` | 必要服务、特征或主通知不可用，会话已停止。调用中央管理器的 `cancelPeripheralConnection` 结束此次连接。 |
| 用户断开 / 系统断开 | 主动断开时先 `close()` 取消本地排队和巡检，再由中央管理器取消外设连接。在 `didDisconnectPeripheral` 中释放会话引用，重连时创建新实例。 |

```swift
// 用户点「刷新状态」时调用。首次连接的巡检由 open() 自动安排。
session.inspect()

// 用户单独查询当前状态时调用，在 onFrame 中处理 3-20 回复。
try session.send(.query(.state))

// 用户选定文件后单独发起下载。先结束巡检，避免它的文件列表查询与显式传输交错。
session.cancelInspection()
try session.send(.download("note20260710-162938.wav", offset: 0))
```

`RecorderCommand` 覆盖查询、校时、普通录音、实时流、增益、文件下载和删除。协议调试可用 `send([UInt8])` 封包，或 `sendRawFrame(Data)` 原样整帧写入。授权码属于设备信息，应避免写入普通日志。

判断按键后的状态要区分三个时间点。① `send` 成功表示帧已入队，系统写缓冲已满时会等待。② `onWrite` 表示已向 CoreBluetooth 提交，采用有响应写时队列还会等待 GATT 写回调再发下一帧。③ 业务结果看设备通知。特别是机身保存，收到 `03 03` 时应继续接收尾音，等按键后发出的状态查询返回 `03 14 02`（空闲）再结束。文件名和大小通过文件列表核对。

回归入口为 `QS668CoreTests/WebDemoTests.swift`。其中四个确认整帧的预期字节取自上述网页脚本的实际回放，并覆盖双服务、双通道拆包、CRC、参数异常和文件偏移。实机对照步骤见[录音卡使用指南](录音卡使用指南.md)。
