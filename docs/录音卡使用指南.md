# CB08 / QS668 录音卡使用指南

这张卡可以通过机身按键录音，通过蓝牙向应用发送状态和实时音频，通过 USB 读取保存在卡上的录音原件。第一次使用时，可以先在网页上完成一次开始、暂停、继续、保存，再用同一张卡在 App 中重复。网页是接入示例和通信行为的对照标准。[打开录音卡 Demo](https://aipixdot.com/airecord/)

## 第一次连接

1. 打开录音卡，拔掉 USB 数据线。如果卡已连接其他网页、手机或桌面 App，先在那个客户端断开。
2. 用支持 Web Bluetooth 的 Chrome 或 Edge 打开 Demo，点「连接设备」，在浏览器的设备选择框选 CB08 或 QS668。如果常规列表没有出现设备，可以点「扫描全部设备」。网页会验证实际服务和通信特征。
3. 在网页底部「通信日志」确认数据通知已开启，再看按键通知是否成功。连接后网页会依次读取电量、容量、固件、授权码、录音状态、时长、文件名、增益和文件列表。个别读项没有回复时，仍可接收其他通知。
4. 如需校时，设备空闲时点「同步时间」。设备接收的是电脑的本地年月日和时分秒。用下一条录音文件名核对时间。

## 用机身按键录一段

按机身开始键，在网页「通信日志」里找带有 `03 01` 的 RX。使用 AE20 服务时，卡可在 AE23 或 AE22 上报按键，网页通过 AE21 写回 `03 02 01`。TX 记录准备写入的回包。网页写入成功后，会再记一条标明该按键「已应答」的 ACK。点「读取项巡检」可再读实际状态、时长和文件列表。[四种按键的回包对照](录音卡协议.md#机身按键)

按保存键后，即使已经看到 `03 04 01`，也请保持连接。等录音状态回到「空闲」，再点「读取列表」核对文件名和大小。这样可以区分设备仍在写文件、实时接收已经结束和文件已经落盘这三个阶段。

机身已经在录音时，可直接连接并观察已有的状态和音频。网页「开始实时」用于主动发起实时录音。CB08 V1.0.0 在已有机身录音中收到该指令，历史实测曾另起一个文件。如果只是中途接入，直接监听即可。

## 在 Mac App 里使用

| 操作 | 工作留声 | 独立 QS668 App（学科网音频采集卡） |
| --- | --- | --- |
| 连接 | 在录音卡页点「选择录音卡…」，在目标设备旁点「使用」 | 设备区点「连接」，有多个候选时选择本机录音卡 |
| 机身启停 | 按卡上的键，状态栏显示录音、暂停或保存，收到音频后生成实时字幕 | 按卡上的键，录音页跟随设备，保存实际收到的实时片段 |
| 再读设备信息 | 「设置 → 录音卡 → 刷新状态」 | 设备菜单「刷新状态」 |
| 校时 | 卡空闲时点「同步时间」 | 设备菜单「同步时间」 |
| 获取原件 | 录音保存后接 USB，App 核验并归档。按设置自动或手动同步 | 通过 USB 同步原件，核对 BLE 片段的完整性 |

在工作留声中换卡时，在设备页点「切换设备…」，在新卡旁点「使用」。只查看列表会保留原连接。工作留声会验证所选设备的录音服务。独立 QS668 App 可用「扫描全部设备」查找广播名称或服务不完整的设备。

工作留声的全天归档、实时字幕与独立 App 的实时采集是两种用途。它们使用相同的蓝牙会话和按键应答。网页保留原始命令、分段导入和删除等调试入口。SDK 的对应操作见协议文档。USB 归档成功后的自动清理由各 App 的归档设置控制，与网页的 BLE 删除按钮分开。

## 在网页核对音频与文件

- **实时音频**。设备空闲时点「开始实时」。看到文件名和接收字节持续增长，说明客户端正在收音。结束后可保存原始音频。网页的设备 OPUS 转写还需要其后端 ASR 服务可用。
- **完整文件**。先点「读取列表」。选 WAV 或 OPUS，或填写文件名与起始偏移后点「导入文件」，从头读取用偏移 0。以设备的启动通知、数据包和成功结束通知核对结果。大段录音可用「分段导入」，Start、End 均为字节偏移。
- **删除**。在网页勾选允许删除，再对单条或全部文件进行确认。需要保留的原件先导出。终止导入只中止当前传输。

## 按键后疑似断联时查看什么

先记下按键时间、固件和文件名，再取按键前后同一段日志。比较一次开始按键时，可以按下表找对应记录。App 的收包记录来自业务回调，确认可能先出现在日志中，按同一次操作的命令和时间配对即可。

| 客户端 | 到哪里看 | 收到开始键与写出确认 | 连接结束的记录 |
| --- | --- | --- | --- |
| 网页 Demo | 「通信日志 → 导出日志」 | RX 中有 `03 01`，TX 为 `3-2`，对应的 ACK 标明机身按键 | INFO 显示「设备已断开」 |
| 工作留声 | 打开 macOS「控制台」，选当前 Mac 并开始流传输，启用信息消息，按子系统 `WorkRecorder`、类别 `RecorderBLE` 过滤 | `BLE key RX … 3-1` 与 `BLE key acknowledgment 3-2` | `BLE disconnected:` 对应系统断开回调。`BLE connect failed:` 表示连接尝试失败 |
| 独立 QS668 App | 默认录音库中的 `~/Music/QS668录音/sync.log`，时间为 UTC | `BLE_RX … 3-1` 与 `BLE_TX`，后者整帧末尾为 `030201` | `BLE_DISCONNECTED` 对应系统断开回调，`BLE_ADAPTER_UNAVAILABLE` 表示 Mac 蓝牙不可用 |

如果只看到时长停更，先手动刷新状态，核对是否又收到回复。如果出现断开记录，标出是否主动断开或插入 USB，再用卡上最终保存的原件核对断开期间的音频。仅凭按键确认或界面时长无法判断哪一端引起了断开。

## 同卡验收

在同一台电脑、同一张卡和同一固件上，先用网页，再断开网页，用待验 App。分别重复开始、暂停、继续和保存，记录每次按键后的确认、断开回调、首个音频包和最终文件。再测录音中途接入、手动断开后重连、文件列表和一个完整样本的大小或 SHA-256。通过回放只能验证客户端发出的字节及状态处理，设备是否仍短断联以这组实测为准。
