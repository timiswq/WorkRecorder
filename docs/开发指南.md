# 开发指南

## 源码职责

模块名和 SwiftPM 产品名沿用现有接口，目录只划分职责。

| 入口 | 职责 |
| --- | --- |
| `WorkRecorder/MyApp.swift` | Xcode 与 SwiftPM 共享启动入口、应用图标资源 |
| `Sources/WorkdayMac/App` | App 场景、生命周期、AppModel 协调、命令 |
| `Sources/WorkdayMac/Workspace` | 全天事项、历史、原始录音、日期与分栏布局 |
| `Sources/WorkdayMac/Captions` | 实时接收、选路、历史、时间尺、回听、桌面气泡 |
| `Sources/WorkdayMac/Device` | 蓝牙观察、USB、原件校验与同步 |
| `Sources/WorkdayMac/Status` | 菜单栏、全局状态、桌面窗口协调 |
| `Sources/WorkdayMac/Playback`、`Voice`、`Settings` | 播放器、声纹与反馈、偏好设置 |
| `Sources/WorkdayMac/Shared`、`Diagnostics` | 共用界面组件、显式启用的演示和隔离整窗验证 |
| `Sources/WorkdayCore` | 按 Archive、Audio、Captions、Device、Processing、Timeline、Voice 分目录的业务与数据处理 |
| `Sources/WorkdayCore/Resources` | 随包 CAM++ 声纹模型与 Silero VAD 模型 |
| `Sources/QS668Core` | 协议、BLE 会话与写队列、实时封包、转写接口；保持独立 SDK 对照路径 |
| `Tests` | 三个测试目标，Mac/Core 测试按职责分目录 |
| `Resources` | Info.plist、App 图标和第三方许可 |
| `script` | 构建、测试、DMG、音频样本和协议对照工具 |

`WorkRecorder.xcodeproj/project.xcproj` 是本项目实际使用的工程配置文件。业务源码由本地 Swift Package 提供，目录调整无需手动维护逐个 Swift 文件的编译列表。不要改应用 bundle ID 或数据目录来配合源码整理。

## 构建、测试和交付

```sh
./script/build_and_run.sh --build-only
./script/test.sh
./script/test.sh --full
./script/capture_scene.sh --no-build
./script/package_dmg.sh
```

构建默认 Release；设置 `WORKDAY_CONFIGURATION=debug` 可构建 Debug。脚本的构建输出都位于仓库外。直接使用 SwiftPM 时，也必须提供仓库外 `--scratch-path`。

普通测试不需要外部音频。`--full` 使用 `~/Documents/CodexArtifacts/WorkRecorder/fixtures/`，也可通过 `WORKDAY_FIXTURES` 指向完整副本。必要内容为：

- `apple/card.opusraw`、`apple/edges.opusraw`：合成的录音卡音频输入。
- `public-voices/`：公开说话人样本，包含 `fangjun-test-sr-1.wav`、`fangjun-sr-2.wav`、`leijun-test-sr-2.wav` 及配套 Opus。
- `workspace/Records/`、`workspace/Days/`：示例资料库；脚本复制临时副本再运行窗口和业务测试。

本机中文识别验收依赖已安装的 Apple 识别模型。当前机器的系统识别结果不能代表所有 macOS 14+ 环境。按需用 `./script/test.sh --filter 测试类型或方法名` 缩小检查范围。资源声明改变后若增量测试漏拷模型，使用新的仓库外 scratch 目录重建，先区分构建缓存问题与业务回归。

`capture_scene.sh` 后台隐藏启动临时 App，以独立 bundle ID 和复制的资料库捕获真实 Window 场景，包括原生窗口按钮；覆盖浅色、深色和窄窗，并记录前台焦点检查。成功与失败结果分别保存，结束后清理临时 App 和资料库。`--no-build` 只适用于当前输出目录已有本轮构建的 App。

打包脚本校验签名、应用标识和 arm64 架构，使用当前输出目录已构建的 App 生成 DMG 及 SHA-256。当前交付为本地签名，未做 Developer ID 签名或 Apple 公证。不要仅凭编译成功认定实机业务通过。

## 维护经验

- **数据先于界面。** USB 原件须校验大小和 SHA-256 后再清理卡内对应副本。原件保存、卡内清理、文字处理是三个独立结果。
- **字幕保持同一身份。** 本机草稿、稳定云端文字和文件转写修订更新同一字幕记录；气泡与历史同步修订。选中文字与开启回听是独立动作，浏览位置由模型保存。
- **声纹反馈绑定原音频。** 本人/非本人反馈须绑定同一句的音频、向量和样本。短句没有足够可用语音时，不应把字幕标记当作已学会声纹；实时 Opus 与归档 WAV 的跨路径准确率需要人工标注验证。
- **窗口保持稳定尺寸。** 桌面气泡用固定尺寸 AppKit 容器承载 SwiftUI；避免内容尺寸反复驱动窗口布局。滚动通知延迟到布局结束后发布，避免在布局回调中修改 ObservableObject。
- **控制全局刷新。** 音频高频输入与界面发布分开，合并重复状态，只在需要的区域刷新。性能结论需说明 Debug/Release、输入方式、窗口可见性和计量时长。
- **状态由共同模型解释。** 主窗口与菜单栏共用状态表达；录音卡异常与 Mac 转写错误分别处理。录音时长以最近设备回复校准，过期后停止推算。
- **保留可恢复的处理进度。** 转写批次、人工事项归属与已保存摘要均属于资料库，不能在重试或开发清理时重置。

## 协议维护

命令编码与按键应答在 `RecorderProtocol.swift`，单连接订阅和写入在 `RecorderGATTSession.swift`、`RecorderWriter.swift`；应用重连和接收边界在 `Device/CardObserver.swift`，状态解释在 `WorkdayCore/Device/CardState.swift`。

```sh
node script/verify_recorder_demo.mjs ~/Documents/CodexArtifacts/WorkRecorder/fixtures/recorder-demo/app.js
./script/check_recorder_sdk.sh /path/to/recorder-sdk/native
```

第一个命令可离线回放固定网页脚本；省略参数则下载文档中注明的固定版本。它验证的是该版本的通信契约，网页现状需另行核实。第二个命令对照独立 SDK 的源码、回归样例和两份录音卡文档。SDK 是独立交付物，不依赖本项目旧构建目录。2026-11-11 的历史 SDK 交付副本与当前源码存在差异，保留作追溯；发布新的 SDK 前须另行对齐和验证，不能以该历史副本宣称当前一致。

## 后续开发约定

从 `main` 继续开发；使用 `git diff baseline-2026-11-13..HEAD` 查看基线后的已提交改动，`git diff baseline-2026-11-13` 同时包含未提交改动。新的发布版本递增版本号与构建号，不覆盖基线标签。

正式知识以本仓库文档和现有源码为准。旧聊天、原型与测试报告仅提供历史证据，不能覆盖当前行为。历史性能或准确率结果不自动成为新版本验收结论。

所有原型、截图、日志、下载、构建与测试输出放在仓库外的 `~/Documents/CodexArtifacts/WorkRecorder/`。清理前确认归属与运行依赖，保留正式发布、必要样本、有效报告和用户数据；不要清理钥匙串或真实资料库。
