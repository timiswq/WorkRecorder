# 开发指南

## 源码职责

模块名和 SwiftPM 产品名沿用现有接口，目录只划分职责。

| 入口 | 职责 |
| --- | --- |
| `WorkRecorder/MyApp.swift` | Xcode 与 SwiftPM 共享启动入口、应用图标资源 |
| `Sources/WorkdayMac/App` | App 场景、生命周期、AppModel 协调、命令 |
| `Sources/WorkdayMac/Workspace` | 全天事项、历史、原始录音、日期与分栏布局 |
| `Sources/WorkdayMac/Captions` | 实时接收、选路、历史、时间尺、回听、桌面气泡 |
| `Sources/WorkdayMac/Device` | 蓝牙发现与选卡、USB 同步、Wi-Fi 卡的 GATT 会话与热点传输 |
| `Sources/WorkdayMac/Status` | 菜单栏、全局状态、桌面窗口协调 |
| `Sources/WorkdayMac/Playback`、`Voice`、`Settings` | 播放器、声纹与反馈、偏好设置 |
| `Sources/WorkdayMac/Shared`、`Diagnostics` | 共用界面组件、显式启用的演示和隔离整窗验证 |
| `Sources/WorkdayCore` | 按 Archive、Audio、Captions、Device、Processing、Timeline、Voice 分目录的业务与数据处理 |
| `Sources/WorkdayCore/Resources` | 随包 CAM++ 声纹模型与 Silero VAD 模型 |
| `Sources/WorkdayMac/Resources/DockArtwork` | 正式的原表情、无嘴提醒表情底图，由 SwiftPM 资源包提供 |
| `Sources/QS668Core` | 协议、BLE 会话与写队列、实时封包、转写接口；保持独立 SDK 对照路径 |
| `Sources/WiFiRecorderCore`、`Sources/CRecorderOpus` | B3085 控制与文件协议、实时音频适配、Opus 解码 |
| `Tests` | QS668 协议、Wi-Fi 卡、业务核心和 Mac 应用四个测试目标 |
| `Resources` | Info.plist、App 图标和第三方许可 |
| `script` | 构建、测试、DMG、音频样本和协议对照工具 |

`WorkRecorder.xcodeproj/project.xcproj` 是本项目实际使用的工程配置文件。业务源码由本地 Swift Package 提供，目录调整无需手动维护逐个 Swift 文件的编译列表。不要改应用 bundle ID 或数据目录来配合源码整理。

Dock 图标由 `DockBadgeController` 在主线程统一维护，复用 `deviceStatus(at:)` 与 `pendingSyncBadgeText`；`DesktopCompanion` 的状态更新负责触发过期状态检查。`DockIconArtwork` 缓存八种设备状态 × 有无提醒的 16 种组合，用原生大尺寸符号叠加两张底图，数字始终交给 `NSDockTile.badgeLabel`。同一组合的时长、电量或数量变化不会重复换图，停止观察时清理角标并恢复原应用图标。重新生成默认应用图标时，向 `swift script/make_icon.swift /仓库外/AppIcon.iconset` 提供仓库外目录，再用 `iconutil` 生成正式 `Resources/AppIcon.icns`。

提醒眼神由 `DockReminderGaze` 固定向右上方绘制，避免仅靠素材里的眼形变化在 Dock 小尺寸下变成平视。修改眼睛时需检查 32、56、64 像素下两只眼睛仍独立可辨，且保留与脸部右边缘的白色间隔；不要把系统角标画进图片。

## 构建、测试和交付

完整 App 使用 Xcode 27.2 或更新的 `project.xcproj` 工程格式。仅运行 SwiftPM 测试可使用 Xcode 26.2 或更新的工具链与 macOS SDK；macOS 26 的界面 API 需要对应 SDK，不能只凭 `swift-tools-version: 6.0` 推断更老的 Xcode 也可编译全部界面。CI 选择 Xcode 26.2，通过 SwiftPM 测试与 Release 编译，不在 CI 中打开 App 或执行带真实账号的请求。

构建脚本传入 `CODE_SIGN_IDENTITY=-` 做本地临时签名，不需要维护者的开发者团队。工程不固定个人 `DEVELOPMENT_TEAM`；自行签名交付时在本机或命令行提供自己的设置。

```sh
./script/build_and_run.sh --build-only
./script/test.sh
./script/test.sh --full
./script/capture_scene.sh --no-build
./script/package_dmg.sh
```

构建默认 Release；设置 `WORKDAY_CONFIGURATION=debug` 可构建 Debug。脚本的构建输出都位于仓库外。直接使用 SwiftPM 时，也必须提供仓库外 `--scratch-path`。

普通测试不需要外部音频、API Key 或录音卡；需要外部资源的用例会明确跳过。`--full` 使用 `~/Documents/CodexArtifacts/WorkRecorder/fixtures/`，也可通过 `WORKDAY_FIXTURES` 指向完整副本。外部样本不随公开仓库分发；克隆仓库后直接运行 `--full` 不能自动取得这些样本。必要内容为：

- `apple/card.opusraw`、`apple/edges.opusraw`：合成的录音卡音频输入。
- `public-voices/`：公开说话人样本，包含 `fangjun-test-sr-1.wav`、`fangjun-sr-2.wav`、`leijun-test-sr-2.wav` 及配套 Opus。
- `workspace/Records/`、`workspace/Days/`：示例资料库；脚本复制临时副本再运行窗口和业务测试。

`python3 script/make_demo.py /path/outside/repository/demo` 可使用系统语音生成合成 WAV 与时间标记文字，供隔离资料库和界面演示使用；这一步不会自动生成 `--full` 的整套目录。`python3 script/test_voice_samples.py /path/outside/repository/public-voices` 可准备公开说话人样本，另需带 libopus 编码器的 ffmpeg。对外分享前确认音频来源及许可，不以真实资料库代替示例资料。

本机中文识别验收依赖已安装的 Apple 识别模型。当前机器的系统识别结果不能代表所有 macOS 14+ 环境。按需用 `./script/test.sh --filter 测试类型或方法名` 缩小检查范围。资源声明改变后若增量测试漏拷模型，使用新的仓库外 scratch 目录重建，先区分构建缓存问题与业务回归。

苹果实时识别有时只给整条草稿一个时间范围。当文字连续至少 800 毫秒音频没有增加，草稿又给出句号、问号或感叹号时，`AppleCaptionPhrases` 会记住这个位置。后续有新词才分行，苹果仍能修订两边的文字和回听范围。回归时要同时看录音中的两行和最终定稿。设置 `WORKDAY_FW925_SPEECH` 指向仓库外的 FW925 三句口述样本（按原时间轴排列的 40 字节 Opus 包），再运行 `./script/test.sh --filter testFW925Spoken`，可复验开会、发纪要、报预算的连续场景。

`capture_scene.sh` 后台隐藏启动临时 App，以独立 bundle ID 和复制的资料库捕获真实 Window 场景，包括原生窗口按钮；覆盖浅色、深色和窄窗，并记录前台焦点检查。临时 App 和示例资料库存放在系统用户临时目录，避免 macOS 对新签名 App 读取「文稿」的授权等待。结果回存仓库外的验证目录，运行结束后清理临时副本。`--no-build` 只适用于当前输出目录已有本轮构建的 App。

打包脚本校验签名、应用标识和 arm64 架构，使用当前输出目录已构建的 App 生成 DMG 及 SHA-256。当前交付为本地签名，未做 Developer ID 签名或 Apple 公证。不要仅凭编译成功认定实机业务通过。

## 选卡与同步

- `RecorderDiscovery` 负责选择窗口的扫描。用户确认目标后，`CardObserver` 验证蓝牙服务，连接就绪才更新绑定。取消浏览会停止这次扫描，原连接继续工作。
- `USBMonitor.detectedVolumes` 是可供选择的磁盘，`volumes` 只包含当前选中且 UUID 唯一的挂载卷。目录读取和归档前后都要核对卷身份。同名磁盘可用路径区分，UUID 重复时暂停同步。仅接 USB 的选择与蓝牙设备关联分别保存。
- 菜单或按钮创建时保存 `RecorderSyncTarget`。执行前重新核对当前目标，避免换卡后用旧操作同步另一张卡。`USBSelectionTests` 覆盖选卡、同名录音、重复标识和切换后的同步操作。

## 维护经验

- **数据先于界面。** USB 原件须校验大小和 SHA-256 后再清理卡内对应副本。原件保存、卡内清理、文字处理是三个独立结果。
- **字幕保持同一身份。** 本机草稿、稳定云端文字和文件转写修订更新同一字幕记录；气泡与历史同步修订。选中文字与开启回听是独立动作，浏览位置由模型保存。
- **声纹反馈绑定原音频。** 本人/非本人反馈须绑定同一句的音频、向量和样本。短句没有足够可用语音时，不应把字幕标记当作已学会声纹；实时 Opus 与归档 WAV 的跨路径准确率需要人工标注验证。

实时滚动窗口、模板学习边界、诊断模式和回退参数见 [实时声纹](实时声纹.md)。三阶段效果报告和原始验证输出保存在仓库外 CodexArtifacts，不将未标注历史的通过数量表述为本人准确率。
- **窗口保持稳定尺寸。** 桌面气泡用固定尺寸 AppKit 容器承载 SwiftUI；避免内容尺寸反复驱动窗口布局。滚动通知延迟到布局结束后发布，避免在布局回调中修改 ObservableObject。
- **控制全局刷新。** 音频高频输入与界面发布分开，合并重复状态，只在需要的区域刷新。性能结论需说明 Debug/Release、输入方式、窗口可见性和计量时长。
- **全天回顾优先呈现内容。** 日期仅在列表页头显示，概述默认四行，待办折叠；上午、下午、晚上分组保留原话。`ProcessingPresentation` 从实际调度对象、计划队列和暂停状态生成 `DayOverviewState` 与 `RecordingProcessingState`，区分进行中、真实自动排队和需要手动操作。`ProcessingStatusView` 将只读进度与可点击按钮分开；忙时按日期启动通过现有逐录音队列处理，保持未选择日期的处理范围。底栏使用同一钟点时间尺定位与播放，`WorkspacePlayback` 保留逐句范围和跨日期来源；详情由 `ActivityInspector`、`RawConversationInspector` 与 `DayTranscriptContent` 组合。
- **状态由共同模型解释。** 主窗口与菜单栏共用状态表达；录音卡异常与 Mac 转写错误分别处理。录音时长以最近设备回复校准，过期后停止推算。
- **保留可恢复的处理进度。** 转写批次、人工事项归属与已保存摘要均属于资料库，不能在重试或开发清理时重置。

## 协议维护

B3085 / FW925 的实时音频格式、录后同步、回放覆盖与真机联调步骤见 [Wi-Fi 录音卡开发指南](Wi-Fi录音卡开发指南.md)。以下 SDK 对照命令用于 QS668 / CB08。

命令编码与按键应答在 `RecorderProtocol.swift`，单连接订阅和写入在 `RecorderGATTSession.swift`、`RecorderWriter.swift`；应用重连和接收边界在 `Device/CardObserver.swift`，状态解释在 `WorkdayCore/Device/CardState.swift`。

```sh
node script/verify_recorder_demo.mjs ~/Documents/CodexArtifacts/WorkRecorder/fixtures/recorder-demo/app.js
./script/check_recorder_sdk.sh /path/to/recorder-sdk/native
```

第一个命令可离线回放固定网页脚本；省略参数则下载文档中注明的固定版本。它验证的是该版本的通信契约，网页现状需另行核实。第二个命令对照独立 SDK 的源码、回归样例和两份录音卡文档。SDK 是独立交付物，不依赖本项目旧构建目录。2026-11-11 的历史 SDK 交付副本与当前源码存在差异，保留作追溯；发布新的 SDK 前须另行对齐和验证，不能以该历史副本宣称当前一致。
